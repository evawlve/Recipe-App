## Pass order (derived from `runParse()` in `src/app/api/nlp/parse/route.ts` on `ffe31cc8`)
1. **Split source**, exactly one of:
   - item-form input (`items[]`): **no route pass runs**.
   - `singleItemFromText()` (`route.ts:53`): the trimmed line is ≤ 60 chars, including any `for/at/as <meal>` suffix. After the suffix is stripped, the line has no `, ; + & \n` / `and` / `with` / `plus`, **is not `isPourOntoSecondFood()` (#514, `route.ts:68`)**, and has ≤ 6 words. One item, and **no route pass runs**.
   - otherwise one of: a SegmentationCache hit, the LLM split (`segmentTextWithAi`), or, when the LLM errors or times out, the `forceSegmentText` heuristic. Then `capSplit`, then the cache write, which keeps the UNPROCESSED split.
2. Segmenter branch only. Every pass is keyed on `lineKey = canonicalizeSegLine(text)` (`route.ts:397`), never on the raw text:
   **`restoreLeadingPour` (#514, `:449`) → `resolveSelfCorrections` (#516, `:452`) → `dropNegatedParts` (`:460`) → `dropDishParts` (#517, `:468`) → `foldDrinkMilk` (#515, `:475`) → `foldTrailingQuantityClauses` (`:480`) → `fillRestaurantBrand` (`:491`)**.
   On `origin/master`, #525 inserts `dropSegmenterEchoes` between `foldDrinkMilk` and `foldTrailingQuantityClauses`. No finding below depends on it: every route reproduction fails identically on master.
3. Every item on every path goes through `parseIngredientLine(rawText)` (`route.ts:547`, and again in the mapper). Its order is `stripQuantityHedges` (**#518** `stripHedgeBeforeArticleMeasure` first; the `-ish` hedges read **#519**'s widened `HEDGEABLE_UNIT_SOURCE`) → `resolvePackageMultipliers` (**#519** kilo units) → `resolveLoosePourMeasures` → tokenise → `normalizeUnitToken` (**#519**). In the mapper, `normalizeIngredientName` (**#509**, the committed JSON via `readRulesFile()`) keys the line, and the rerank query is `aiCanonicalBase || stripPrepModifiers(...)` (`map-ingredient-with-fallback.ts:2318`, `:3834`).

So #509, #518 and #519 reach every line. #514's short-path decline reaches every line that starts with a pour. #514's restore and #515–#517 reach only segmenter lines.

### What the findings say about each pass
- **#514:** the split side holds on every ≥2-item split I tried. Two gaps remain. A one-item split (heuristic fallback or echo) brings F9 back (C1). The new leading-preposition strip is not scoped to the vehicle food, so it renames chains and egg styles (C7). The predicate is broad on non-food objects, which costs latency only (C15).
- **#515:** "positive evidence" is decided on surface tokens alone. A pronoun counts as evidence (C11) while a bare `with`-object food does not (C6), and the split, which knows the object is a food, is never consulted.
- **#516:** the F3 tail window is both too narrow (stops at the comma piece: C4; skipped on a null span: C5) and too wide (any ADD word, even as a modifier or a joiner: C10). The F4 guard is narrower than the main-loop guard it says it mirrors (C3).
- **#517:** a word set cannot tell "a new clause" from "the next step of the same build" (C13) or a provenance phrase longer than one word (C12), and it misses clause words it does not list (C2).
- **#518 / #519:** parse-side regressions are limited to `1 kilo kai` (C9, low realism). The article-hedge strip covers only the units on its hand list (C14). #509 holds in the normalizer but is undone at rerank whenever there is no canonicalBase (C8).

type It = { rawText: string; normalizedForm: string; brand: string };
const s = (r: string, n = r.replace(/^(a|an|the|some)\s+/i, '')): It => ({ rawText: r, normalizedForm: n, brand: '' });
// route.ts runParse() order on ffe31cc8: pour restore -> correction -> negated drop -> dish -> drink -> trailing fold (brand fill omitted)
function chain(line: string, items: It[]): string[] {
  const k = canonicalizeSegLine(line);
  let x = restoreLeadingPour(k, items).items;
  x = resolveSelfCorrections(k, x).items; x = dropNegatedParts(k, x).items; x = dropDishParts(k, x).items; x = foldDrinkMilk(k, x).items;
