## Pass order (derived from `runParse()` in `src/app/api/nlp/parse/route.ts`)
1. **Split source**, exactly one of these:
   - item-form input (`items[]`): **no route pass runs**.
   - `singleItemFromText()`: ≤ 60 chars, ≤ 6 words, none of `, ; + & \n` / `and` / `with` / `plus` (after a trailing `for <meal>` is stripped). One item. **No route pass runs.**
   - otherwise SegmentationCache hit, or LLM split (`segmentTextWithAi`), or the `forceSegmentText` heuristic. Then `capSplit`, and the cache write (which keeps the UNPROCESSED split).
2. Segmenter branch only, all keyed by `lineKey = canonicalizeSegLine(text)`:
   `resolveSelfCorrections` (#498, +#501) → `dropNegatedParts` → `dropDishParts` (#496) → `foldDrinkMilk` (#497) → `foldTrailingQuantityClauses` (#494 touched `isValidTarget`/`rewrite`) → `fillRestaurantBrand`.
3. For every item on every path: `parseIngredientLine(rawText)` (`route.ts:540`, and again in `mapIngredientWithFallback`, `map-ingredient-with-fallback.ts:644`). Its internal order is `stripQuantityHedges` (#508) → `resolvePackageMultipliers` → **`resolveLoosePourMeasures` (#494)** → tokenise → **`halfAndHalfCursor` (#495)** guarding `normalizeFractionalMeasure`, the leading-unit read, the quantity read, the multiplier/unit read and the after-paren unit read.
4. Serving: `hydration-lane.ts:930/1846` → `getBareQueryDefault(parsed.name || candidate.name)`, which holds the #495 30 g rule.

So #494/#495 apply to every line, while #496–#498 only reach lines the segmenter handles.

### Proposed fixes (one per finding, mechanism-level, NOT implemented)

- **F1** (VANISH): `dropDishParts()`: end the part list at the first later comma piece that carries words no item span accounts for (`then`, `for dinner`, `later`, `for breakfast`), i.e. a piece with non-item residue is a new clause, not more of the `with` list. Same input class: `..., and later steak with rice and beans` (steak/rice/beans vanish), `..., plus shrimp and rice` (shrimp vanishes), `..., and for lunch tuna with crackers` (tuna vanishes).
- **F2** (VANISH): Same fix as F1 (the piece carries `for breakfast` residue). Also `homemade tacos with steak, and eggs for breakfast` drops the eggs.
- **F3** (VANISH): `resolveSelfCorrections()` step 2: under a marker outside SWAP_OK, accept a restatement only when one item's non-head words are a subset of the other's (`eggs`/`scrambled eggs`), so a conflicting modifier (`turkey` vs `ham`) is a food swap, which the module header says a weak word never does. Secondary: the ADD guard reads only `jw`, so an addition word the segmenter left after j's span (`too`) is invisible; read j's comma piece in `lineKey` instead.
- **F4** (VANISH): `resolveSelfCorrections()` trailing block: apply the same gap guards the main loop uses (no `and` between the two items, no conflicting modifiers) before removing item k; today it needs only head-noun equality plus a numeric clause on the last item.
- **F7** (VANISH): `foldDrinkMilk()`: for the `and` gap, require the milk to END its comma piece (no lineKey tokens after its span in the piece). `for my cereal`, `for the baby` and `for the kids` are words the milk item does not cover. Same input class: `a latte and milk for the baby`, `two lattes and milk for the kids`.
- **F9** (VANISH): `splitLeadingPour()`: return null when `rest` contains a prepositional vehicle phrase (`on`/`in`/`into`/`over` + a noun phrase). A pour onto or into another food names two foods, so leave the line unrewritten; better still, have `singleItemFromText()` treat a leading pour + preposition as multi-item so the segmenter splits it.
- **F8** (IDENTITY): `resolveLoosePourMeasures()`: decline the rewrite when the whole `<pour> of <rest>` phrase is itself a known product/brand name (consult the brand detector `parseIngredientLine` already imports, `detectBrandInQuery`, on the un-rewritten line) instead of rewriting first and asking later.
- **F11** (IDENTITY): `resolveSelfCorrections()` step 4: when j has no head noun of its own (a lone modifier, `decaf`/`iced`/`unsweetened`), prefix it onto the previous item instead of swapping. The DET guard catches only a determiner-led earlier item (`a coffee, make it decaf` holds).
- **F5** (PORTION): `resolveSelfCorrections()`: canonicalise each item and j through `resolveLoosePourMeasures()` before `parseClause()`/`foodMinusQty()`, so the pour is a clause UNIT (`floz`) and not the food word `splashes` (which `sameWord` matches to `splash` and discards). Same root as F13.
- **F6** (PORTION): `foldDrinkMilk()`: compute the gap over items that survived the earlier passes, not raw `lineKey` adjacency. After self-correction removes `whole milk`, the remaining gap `with whole milk actually` should count as a pure correction gap, so `oat milk` folds. Alternatively, self-correction step 2 should hand the replacement to the drink fold as the drink's milk.
- **F10** (PORTION): `resolveSelfCorrections()` step 2: when the earlier item carries a quantity and j carries none, keep k's quantity (a restatement with no number corrects identity, not count), e.g. rewrite to `2 really good eggs`.
- **F12** (NO-FIRE (+NOISE: `three` mapped as a food)): `resolveSelfCorrections()` step 1: a quantity-only j should target the FIRST live item of the previous comma piece (the piece head) when j-1 is not alone. Today it needs j-1 alone in its piece, so any `with` part blocks the brief's own flagship shape.
- **F13** (NO-FIRE (+NOISE)): Same as F5: `parseClause()` does not know the pour words as units, so `two swigs` is not quantity-only.
- **F14** (NO-FIRE (PORTION effect)): `foldDrinkMilk()`: scan forward from the drink across items in the same comma piece joined only by `with`/`and` (drink modifiers), not only `d+1`.
- **F15** (NO-FIRE): `dropDishParts()`: continue the dish loop after a dish's list ends (do not `return` inside the `for d` loop), so each dish with its own marker drops its own parts.
- **F16** (NO-FIRE): `getBareQueryDefault()` HH rule: allow an optional leading article/count (`^(?:a|an|\d+)?\s*half...`), or strip a leading article from `parsed.name` once before the category lexicon.
- **F17** (NO-FIRE): `isHalfAndHalfAt()`: compare token k+2 with `sameWord`-style plural folding (`half`/`halfs`/`halves`) instead of exact `half`.
- **F18** (NO-FIRE): `POUR_RX`: accept one optional size adjective between the count and the pour word, scaling nothing. The amount stays a convention, the same way `half a splash` is listed as a gap.

### What the findings say about each pass

- **#496 dish-part-drop:** the part list has no clause boundary. Determiners and numbers end it, but `then`, `later`, `plus`, `for dinner`, `for breakfast` and comma pieces without an article do not. With the segmenter's habit of emitting bare part nouns, a whole second meal of bare known parts (protein, filling) is deleted (F1, F2). This is the worst class found.
- **#498 self-correction:** a restatement is recognised by the head noun alone, so under a WEAK marker it swaps two different foods that share a head (F3), contrary to the module's own rule. The trailing kind has none of the gap guards (F4). The pour words are invisible to `parseClause` (F5, F13), and the quantity-only path cannot reach past a `with` part (F12).
- **#497 drink-milk-fold:** the `and` gap trusts adjacency and ignores words after the milk (F7). After a correction it no longer sees the corrected milk (F6, on captured splits).
- **#494 loose-measures:** it rewrites before it knows the phrase is a measure, so a product name (F8) or a pour onto another food (F9) is billed as half an ounce. F9 is on the single-item fast path, so no segmenter can rescue it.
- **#495 half-and-half:** the parse side held on every input I tried. Only the anchored bare-query regex (F16) and plural `halfs` (F17, pre-existing) leak.

```ts
// cloud-35 reproductions. Each test asserts the CORRECT outcome, so a FAIL is the finding.
import { parseIngredientLine } from '@/lib/parse/ingredient-line';
import { getBareQueryDefault } from '@/lib/ai/ambiguous-serving-estimator';
import { resolveSelfCorrections } from '@/lib/nlp/self-correction';
import { dropNegatedParts } from '@/lib/nlp/negated-part-drop';
import { dropDishParts } from '@/lib/nlp/dish-part-drop';
import { foldDrinkMilk } from '@/lib/nlp/drink-milk-fold';
import { foldTrailingQuantityClauses } from '@/lib/nlp/trailing-quantity-fold';
import { canonicalizeSegLine } from '@/lib/nlp/seg-line-key';
type It = { rawText: string; normalizedForm: string; brand: string };
const s = (r: string, n = r.replace(/^(a|an|the|some)\s+/i, '')): It => ({ rawText: r, normalizedForm: n, brand: '' });
// route.ts runParse() order: correction -> negated drop -> dish -> drink -> trailing fold (brand fill omitted: no brands here)
function chain(line: string, items: It[]): string[] {
  const k = canonicalizeSegLine(line);
  let x = resolveSelfCorrections(k, items).items;
  x = dropNegatedParts(k, x).items; x = dropDishParts(k, x).items; x = foldDrinkMilk(k, x).items;
  return foldTrailingQuantityClauses(k, x).items.map(i => i.rawText);
}
const raw = (r: { items: { rawText: string }[] }) => r.items.map(i => i.rawText);
```
