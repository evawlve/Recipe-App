# =============================================================================
# WHY THIS FILE EXISTS. #356's first winner-gate ran 325 rows (75 cold seeds +
# 250 sampled from 30 days of MappingEventLog) and the FatSecret hunk — the

# Playbook §2: a gate's population must contain the cases the change is
# supposed to CREATE. This file is that population.

# and lines that START with `#` — it does NOT strip a trailing comment, so every
# annotation here sits on its own line above the query it describes.

#        -r tsconfig-paths/register scripts/eval/winner-diff.ts'

#                         --out /tmp/probe-snap.json
#           assert the intended fs_<id> appears in entries[].candidates[].

# ADVERSE — these MOVE, and they move the WRONG WAY. Kept in the population on
# purpose: the gate exists to report them, not to be kept clean of them.
#
# `labelLeadingCount()` reads `^\s*(\d+(?:\.\d+)?)`, so on "2/3 spear" it reads
# the NUMERATOR 2, calls it an integer piece count >= 2, and `servingLabelCountsPiece`
# now agrees because the branch can finally read the label word `spear`. That puts
# a non-null `labelPieceCount` first in the `??` chain and `labelFractionQuantity`
# is never consulted. Master divided by numberOfUnits (1); the branch divides by 2;
# the label says 2/3, i.e. divide by 0.667. 14 g is the only one of the three
# readings the label does not support.
#
# Corpus-wide this is 401 disagreeing rows, but 397 of them carry the label word
# `cup`, so a cup request is intercepted by the volume branch and never reaches
# the piece fallback. THREE rows are actually reachable: fs_4655924 and
# fs_22330689 (Vlasic / Great Value kosher dill spears, "2/3 spear" 28 g) and
# fs_34355793 (Stonyfield organic yogurt, "3/4 serving" 5 g -> 1.7 g).
